# プラグイン開発・使用ガイド

## プラグインとは

プラグインは 1 つ以上のツールを宣言する JSON ファイルです。AI がいつツールを呼ぶか判断してパラメータを埋め、DevCodex があなたの書いたテンプレートで HTTP リクエストを送り、応答を AI に返します。

向いている用途：天気照会、Home Assistant、n8n ワークフロー、自作 API、社内システム。

## プラグインとスキルの違い

| 種類 | 役割 | 形式 |
| --- | --- | --- |
| プラグイン | AI に手を増やす：外部 HTTP エンドポイントを呼ぶ | JSON |
| スキル | AI に知識を増やす：方法と手順の説明 | SKILL.md |

両者は併用できます。スキルがやり方を説明し、プラグインが呼び出すツールを提供します。

## クイックスタート

下の JSON をコピーし、プラグインページ右下のボタンをタップして貼り付けインストールを選びます。

```json
{
  "id": "weather-demo",
  "name": "天気照会",
  "version": "1.0.0",
  "author": "あなたの名前",
  "description": "都市の天気を照会",
  "tools": [
    {
      "name": "get_weather",
      "description": "ユーザーが都市の天気を尋ねたときに呼び出す",
      "parameters": "{\"type\":\"object\",\"properties\":{\"city\":{\"type\":\"string\",\"description\":\"英語の都市名、例：Beijing\"}},\"required\":[\"city\"]}",
      "endpoint": {
        "method": "GET",
        "url": "https://wttr.in/{{city}}?format=3"
      }
    }
  ]
}
```

インストール後、チャットで「Beijing の天気を調べて」と言えば AI が自動で get_weather を呼び出します。

## フィールド解説

### プラグイン層

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| id | はい | 一意の識別子。同じ id で再インストールすると旧版を上書きします |
| name | はい | 表示名 |
| version | いいえ | バージョン番号。既定は 1.0.0 |
| author | いいえ | 作者 |
| description | いいえ | プラグインの説明 |
| enabled | いいえ | 有効かどうか。既定は true |
| tools | はい | ツール一覧。最低 1 個 |

### ツール層（tools の各項目）

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| name | はい | ツール名。英語で、空白は不可 |
| description | いいえ | いつ使うかを明確に。AI はこれで呼び出すか判断します |
| parameters | いいえ | JSON Schema の文字列形式。既定は {} |
| endpoint | はい | HTTP リクエスト設定 |

### エンドポイント層（endpoint）

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| url | はい | リクエスト URL。{{パラメータ名}} をサポート |
| method | いいえ | GET、POST、PUT、DELETE。既定は POST |
| headers | いいえ | リクエストヘッダー。値に {{パラメータ名}} をサポート |
| bodyTemplate | いいえ | リクエストボディテンプレート。POST と PUT で使用 |
| resultPath | いいえ | JSON 応答から結果を取り出すパス |

## パラメータの書き方

parameters は JSON Schema を入れた文字列で、内部の二重引用符は `\"` とエスケープします：

```json
"{\"type\":\"object\",\"properties\":{\"city\":{\"type\":\"string\",\"description\":\"都市名\"}},\"required\":[\"city\"]}"
```

すべてのパラメータに description を書いてください。AI はそれを見て正しい値を入れます。parameters の解析に失敗すると、ツールはパラメータなしに退化します。

## テンプレートの規則

- {{パラメータ名}} は AI が入力した値でそのまま置換され、URL エンコードは行いません。
- URL 内の空白は自動で %20 に変換されます。その他の特殊文字はパラメータ値自体が正しい必要があります。
- パラメータ名と {{}} 内の名前は完全に一致する必要があり、一致しないプレースホルダーはそのまま残ります。
- GET と DELETE はボディを送りません。パラメータは URL と headers 内のプレースホルダー経由でのみ渡せ、プレースホルダーのないパラメータは破棄されます。
- その他のメソッド（POST、PUT、PATCH など）で bodyTemplate がない場合、ボディは AI が入力したパラメータの JSON になります。ある場合はテンプレートどおりに送ります。
- ボディの Content-Type は常に application/json です。

ヘッダーとボディを含む例：

```json
"endpoint": {
  "method": "POST",
  "url": "https://api.example.com/v1/notes",
  "headers": { "Authorization": "Bearer YOUR_KEY" },
  "bodyTemplate": "{\"title\": \"{{title}}\", \"text\": \"{{text}}\"}"
}
```

## 結果の抽出 resultPath

- 空：応答全体を返し、先頭 8000 文字まで保持します。
- data.items：ドット記法で JSON オブジェクトのフィールドをたどります。
- オブジェクトのフィールドのみ対応し、配列の添字は非対応です。
- 途中でパスが存在しない、または応答が JSON でない場合は応答全体を返します（同じく 8000 文字まで）。
- 一致した値は JSON テキストとして返します。文字列フィールドは二重引用符付き、オブジェクトと配列はその JSON 内容を返し、同じく 8000 文字までです。
- 失敗時、AI は HTTP ステータスコードと応答の先頭 500 文字、または ERROR で始まる例外メッセージを受け取ります。

## インストールと検証

3 通りに対応：ファイルからインストール、URL からダウンロード、JSON を貼り付け。インストール時に次を検査します：

1. id と name は空にできません。
2. ツールを最低 1 つ宣言すること。
3. 各ツールに name と endpoint.url が必要です。
4. ツール名に空白は使えません。

同一プラグイン内でツール名が重複しないようにし、プラグイン間でも衝突を避けてください。そうしないと AI が区別できません。

## デバッグ手順

1. JSON を保存してインストールし、プラグインページに表示されスイッチがオンになっていることを確認します。
2. チャットでやりたいことを明確に伝えます。例：「get_weather で Beijing の天気を調べて」。
3. ツールカードを展開し、AI が入力したパラメータと返却内容を確認します。
4. HTTP 4xx が返る場合は headers とパラメータを、ERROR の場合は URL とネットワークを確認します。
5. JSON を修正し、同じ id で再インストールすれば上書きできます。

## 作成のヒント

1. description にはいつ使うかを明確に書き、API の説明だけにしない。
2. API Key は headers に入れ、URL に埋め込まない。
3. 応答が大きい場合は resultPath を設定し、AI が読む量を減らす。
4. 1 つのツールは 1 つのことだけを行い、パラメータはできるだけ少なく。
5. プラグイン JSON はアプリのプライベートディレクトリに平文で保存されます。実際の鍵を含むファイルは共有しないでください。

## スキル（SKILL.md）形式

スキルは Markdown ファイルで、先頭の frontmatter に名前と概要を書きます：

```markdown
---
name: translate
description: 中英翻訳。ユーザーが翻訳を求めたときに使用
---
ユーザーの内容を中国語に翻訳し、すでに中国語なら英語に翻訳して、訳文だけを出力します。
```

- name は必須、description は記入を推奨します。
- description はシステムプロンプトに常駐し、本文は必要時に AI が skill_read で読みます。
- 設定ページのスキル入口からインストールするか、GitHub リポジトリからインポートできます。
